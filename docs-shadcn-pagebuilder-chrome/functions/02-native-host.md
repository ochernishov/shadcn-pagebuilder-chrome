# 2. Native Messaging host

> **Статус:** ✅ работает
> **Зависимости:** [01-extension](01-extension.md) (единственный вызывающий)

## Назначение

Единственный компонент проекта с доступом к файловой системе. Принимает
Native Messaging-сообщения от расширения и пишет пронумерованный пакет
(`Collector/<id>/`) в выбранный пользователем каталог проекта. См.
[ADR-0001](../adr/0001-mv3-extension-native-host-local-first.md).

## Архитектура

- `native-host/host.mjs` — единственный файл; читает/пишет сообщения по
  протоколу Native Messaging (4-байтовая длина + JSON, stdin/stdout).
- Устанавливается через `scripts/install-host.mjs` в
  Application Support — не зависит от скачанного репозитория или релизной
  папки после установки.

## API / Интерфейс

| Действие | Описание |
|---|---|
| `choose-directory` | Открывает нативный диалог выбора папки (macOS) |
| `export` | Выделяет коллизионно-проверенный шестизначный ID, создаёт `<project>/Collector/<id>/`, пишет `page-spec.json`, `PAGE_SPEC.md`, PNG-скриншоты |

## Данные

- Пишет только в каталог, явно выбранный пользователем, либо в
  `<export-root>/<project>/Collector/<id>/` (fallback, оба корня передаёт
  лаунчер через окружение).
- Создаёт `Collector/.gitignore` с deny-by-default правилом — пакеты не
  попадают в целевой репозиторий, пока пользователь не изменит правило вручную
  после санитизации.

## Конфигурация

`NATIVE_HOST_NAME`, `EXTENSION_PUBLIC_KEY` (из него выводится ID хоста),
`EXPORT_DIRECTORY`, `PROJECT_EXPORT_DIRECTORY` — из `.env`.
