# 0001. Расширение Chrome MV3 + локальный Native Messaging host, без бэкенда

> **Статус:** принято
> **Дата:** 2026-08-14
> **Область:** архитектура проекта в целом — расширение, хост, экспорт данных
> **Заменяет:** — · **Связано:** —

## Контекст

Задача — собрать визуальные референсы (блоки, скриншоты, тексты) с любых сайтов
прямо в браузере пользователя и передать их кодирующему агенту (Codex, Claude Code)
как локальный пронумерованный пакет (`Collector/<id>/`) для последующей
реализации. Источник данных — то, что пользователь уже видит на экране, включая
платные библиотеки блоков, к которым нет и не будет программного API.

Данные (URL, заметки, скриншоты) принадлежат конкретному локальному проекту
разработчика на его диске, а не облачному сервису: агент должен найти
`Collector/<id>/` в файловой системе рядом с кодом, который он реализует.

## Решение

Проект реализуется как связка из двух локальных компонентов без какого-либо
сервера:

- **Chrome-расширение (Manifest V3)** — side panel + background service worker,
  собирает метаданные страниц и скриншоты в `chrome.storage.local`, никогда не
  подгружает удалённый код (требование MV3 и `CONTRIBUTING.md`).
- **Node.js Native Messaging host** — единственный компонент с доступом к
  файловой системе; получает данные из расширения через Native Messaging и
  пишет пронумерованный пакет (`Collector/<id>/`) в выбранный пользователем
  каталог проекта.

Собранный пакет резолвится общим скиллом `skills/shadcn-collector/`, который
устанавливается в глобальные каталоги скиллов Codex и Claude Code.

## Альтернативы

- **Веб-сервис с загрузкой в облако** — отклонён: данные (в том числе превью
  платных, но легально просматриваемых библиотек) не должны покидать машину
  пользователя; облачное хранилище добавляет бэкенд, аутентификацию и
  инфраструктуру ради задачи, которая по природе локальная.
- **Расширение без Native Messaging (только `downloads` API)** — отклонено:
  `chrome.downloads` не даёт выбрать существующий каталог конкретного проекта и
  не может писать структурированный пакет из нескольких файлов (JSON + Markdown
  + PNG) в произвольное место рядом с кодом.
- **Генерация кода прямо в расширении** — отклонена: расширение не видит
  структуру целевого репозитория и его конвенций; финальную реализацию должен
  делать кодирующий агент с полным контекстом проекта, расширение — только
  источник фактического визуального референса.

## Последствия

- **Получаем:** данные никогда не покидают машину пользователя; расширение
  остаётся совместимым с MV3 и политиками Chrome Web Store (`CONTRIBUTING.md`,
  `PRIVACY.md`); один и тот же пакет читают и Codex, и Claude Code.
- **Платим:** отдельный шаг установки Native Host (`npm run install:host`) и
  привязка к ID, производному от `EXTENSION_PUBLIC_KEY`; без хоста экспорт
  недоступен — работает только сбор данных внутри расширения.
- **Что теперь запрещено:** синхронизация между устройствами без ручного
  переноса каталога `Collector/`; хранение платного исходного кода блоков
  (запрещено отдельно и по конвенции проекта).

## Условия пересмотра

- Появляется требование делиться собранными пакетами между несколькими
  устройствами/пользователями без ручного копирования каталога.
- Chrome убирает или существенно меняет Native Messaging API.
